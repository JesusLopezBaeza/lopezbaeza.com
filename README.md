# lopezbaeza.com

The personal site of Jesús López-Baeza, urban researcher — projects,
publications, lectures and three small interactive tools.

It is a static site: plain HTML, one stylesheet and a handful of small scripts,
generated by a Python script and served as files. No framework, no build
pipeline, no database, no tracking, no cookies.

---

## Looking at it

Open `index.html` in a browser. Everything works from the filesystem, including
the tools.

## The tools

Three dashboards, under **Tools**. Each one opens empty and does nothing until
you give it a file of your own:

| | reads | draws |
|---|---|---|
| **Career Map** | a spreadsheet of positions, projects and publications | a world map and a timeline of a working life |
| **Ledger** | a spreadsheet of transactions | income, expenses, balance and recurring payments |
| **Flight Log** | a flight diary, or a `flightdiary.net` export | a route map with distances, and nine cross-filtering charts |

Each offers a template to start from.

**Your file never leaves your computer.** It is read in the browser, nothing is
uploaded, no copy is kept and nothing is sent anywhere. Close the tab and the
data is gone. The pages have no server to send it to.

## Rebuilding

Needs Python 3 and `openpyxl`:

```sh
pip install openpyxl
cd build
python3 build.py
```

That regenerates everything in `site/`. Editing the HTML there directly works,
but the next build overwrites it.

Content lives in the Python files in `build/` — one for the bio and navigation,
one for publications, one for events, and so on — plus `style.css`, which holds
all of the design. Nothing is hidden in a template language.

The airport table the Flight Log uses is generated separately and committed, so
an ordinary build does not need it:

```sh
pip install airportsdata
python3 build/airports.py
```

## Publishing

Any static host will serve it: put the contents of `site/` at the root.

For GitHub Pages, that means uploading the files inside `site/` — not the folder
itself — enabling Pages in the repository settings, and keeping two files that
are easy to miss because they start with a dot or have no extension:

- `.nojekyll` — stops the host trying to process the site as a blog
- `CNAME` — the custom domain, if there is one

## Built with

- [Archivo](https://fonts.google.com/specimen/Archivo),
  [Newsreader](https://fonts.google.com/specimen/Newsreader) and
  [JetBrains Mono](https://fonts.google.com/specimen/JetBrains+Mono), served by
  Google Fonts
- [Plotly.js](https://plotly.com/javascript/) for the flight map and charts
- [SheetJS](https://sheetjs.com/) for reading spreadsheets in the browser
- [airportsdata](https://github.com/mborsetti/airportsdata) for the coordinates
  of 7,886 airports

Those last three load only when a tool actually needs them, so the rest of the
site pulls in no JavaScript from anywhere.
